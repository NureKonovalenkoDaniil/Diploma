# Оптимізований план покращення мобільного застосунку (Фаза 5)

**Дата:** 2026-05-03  
**Область:** Mobile/MedicationManagement (Android)  
**Ціль:** створення сучасного і потужного застосунку, який є повноцінним клієнтом системи для всіх типів користувачів (приватні особи, аптеки, лікарні), з підтримкою повного життєвого циклу препаратів.

---

## 1. Принципи (щоб не “роздути” обсяг)
- Не робити повної міграції на Jetpack Compose та архітектурних ускладнень типу Hilt/Room. Використовуємо існуючі XML-екрани з модернізацією.
- Фокус на **універсальності**: додаток підходить як для сценарію "домашня аптечка", так і для професійного обліку в лікарнях чи аптеках (повний CRUD, моніторинг локацій, IoT).
- Спрощена взаємодія: IoT-пристрої додаються легко (тільки за ID), сповіщення виведені на перший план.
- Технічна оптимізація через **Retrofit + Coroutines**, що радикально зменшить кількість коду в порівнянні з поточним `HttpURLConnection`.

---

## 2. Цільовий функціонал мобільного застосунку (Універсальний клієнт)

### 2.1 MUST-HAVE (Обов’язково)
- **Автентифікація:** Login, Register, Logout (очищення токена). Централізований `AuthInterceptor` для безпечної передачі токена.
  - *Реєстрація з підтвердженням пошти:* Додаток відображає екран "Перевірте пошту" після реєстрації. Користувач переходить за лінком у листі через браузер телефону, бекенд підтверджує email, після чого користувач повертається в мобільний додаток для входу.
- **Аптечка (Medicines):**
  - Перегляд, додавання, редагування, видалення.
  - **Quick Action ("Вжити"):** кнопка в списку/деталях, яка швидко списує кількість та реєструє подію "Вжито" у щоденник.
- **Медичний щоденник (Lifecycle):**
  - Перегляд історії дій над конкретним препаратом (Додано, Вжито, Викинуто) на екрані деталей.
- **Датчики (IoT Devices):**
  - Додавання домашнього датчика шляхом простого вводу `DeviceID` з коробки.
  - Перегляд статусу датчиків (Працює / Порушення).
- **Сповіщення (Notifications):**
  - Окрема вкладка з бейджем непрочитаних повідомлень. Головний інструмент контролю термінів та температури.
- **Сучасний вигляд:** Перехід на Material Components, уніфікація кольорів, обробка станів Loading / Error / Empty.

### 2.2 Обмеження мобільної версії (в порівнянні з Web)
- **Повна функціональна відповідність:** Мобільна версія повністю дублює можливості веб-версії, включаючи управління користувачами (Admin-панель для додавання/редагування/видалення користувачів та зміни ролей) та перегляд журналу аудиту (Audit Log).
- **Розширені звіти:** Глибока аналітика та звіти у форматі PDF/Excel (якщо будуть додані) розробляються з пріоритетом для Web-версії, але ключові показники інтегровані в мобільний інтерфейс.

---

## 3. План модернізації (Етапи реалізації)

### Етап A — Архітектура та Стабілізація (Retrofit)
- Заміна `HttpURLConnection` на `Retrofit + Gson/Moshi`. Це прибере дублювання та баги з потоками.
- Використання `ViewModel` + `LiveData` (або `StateFlow`) для збереження стану екранів (захист від втрати даних при повороті екрану).
- Єдиний `TokenManager` (`SharedPreferences`) та глобальна обробка 401 помилки (редирект на Login).

### Етап B — Оновлення UI/UX (Material Components)
- Переведення теми на `Theme.MaterialComponents.DayNight.NoActionBar`.
- Зміна навігації на `BottomNavigationView` з трьома вкладками: **Аптечка**, **Датчики**, **Сповіщення**.
- Додавання спінерів завантаження та екранів помилок.

### Етап C — Імплементація Фіч (Quick Actions та IoT)
- Зв'язка "Аптечки" з `MedicineLifecycleEvent` (Кнопка "Вжити" викликає паралельні PATCH та POST запити).
- Зручний DatePicker для терміну придатності.
- Екран "Додати датчик" з прив'язкою до існуючого API (`POST /api/iotdevice`), де бекенд автоматично робить claim на `OrganizationId` користувача.

---

## 4. Критерії готовності (Definition of Done)
- Користувач може увійти, токен зберігається стабільно, всі запити безпечні.
- Користувач може додати/змінити препарат та зафіксувати його вживання (історія зберігається).
- Користувач бачить сповіщення і може позначити їх як прочитані.
- Користувач може зареєструвати датчик за ID і переглядати його статус.
- UI виглядає сучасно, не ламається при повороті екрану, має стани Loading та Error.
